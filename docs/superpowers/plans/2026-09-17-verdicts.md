# Verdicts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An item is amber until its first Confirm; Confirm (or a Run) turns it green or red on its exact content; an edit returns it to amber; red findings live on the item; the only top-level signal is a one-line "Needs attention" pointer next to Run pipeline. No red before the author asks.

**Architecture:** `stores.ts` replaces the confirmations record with a verdicts record (signature + confirmed/rejected + findings, persisted as `dashi.verdicts`); `issueFindings` moves to `src/findings.ts` so the store, the cards and the groups derive findings the same way. `Cards` and `GroupsEditor` read `verdictOf` for the dot and the findings and stop rendering live probe errors; the Process-tab banner goes; `results.tsx` gains the pointer and records rejected verdicts from a failed run.

**Tech Stack:** SolidJS 2.0.0-rc.6, Vitest 4 + jsdom, pnpm.

**Spec:** `docs/superpowers/specs/2026-09-17-verdicts-design.md`

- **Commits:** one per task on `sdd/post-smoke` (on top of `6caf0d7`); nothing pushed by a task. Messages end with a blank line then `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

- **Solid 2:** `createEffect(compute, effect)`; store/signal setters take updater functions (Solid 2 defers reads: two read-modify-writes in one tick keep only the last); `createMemo` for derived values; store reads in JSX/memos only; tests `await flush()`.
- **States and `data-state` values:** `unconfirmed` (amber, `bg-warning`), `confirmed` (green, `bg-success`), `rejected` (red, `bg-destructive`). Warnings never change the dot. Live probe errors never paint an item.

- **Run stays allowed** with amber or red items.
- **Tests assert; every new assertion is mutation-tested** (make the claim false → the test fails → restore; paste both).

```ts
// --- verdicts -------------------------------------------------------------------------------
//
// What the author has asked about each definition, and what the server answered.
//
// Not in the document and not sent anywhere: an ergonomic mark, kept in `sessionStorage` beside
// the document so a reload brings both back; closing the tab ends them, as it ends the document.
//
// A verdict is bound to a *signature of the content*, never a flag. Editing an item changes its
// signature, so green and red alike expire on edit — the item is back to "not asked" (amber) until
// the next Confirm — and nothing is remembered as wrong or right about content the server never
// saw. It is also what makes the index-based keys safe: removing an earlier card slides every
// later key onto its neighbour, where the signature no longer matches and so reads as unasked.
//
// Decided 2026-09-17: red is reserved for "you asked, and it was wrong". The continuous probe
// never writes here; only Confirm and a Run do.

export type Verdict = {
  signature: string;
  verdict: "confirmed" | "rejected";
  findings: Incompleteness[];
};

const [verdicts, setVerdicts] = persistedSignal<Record<string, Verdict>>("dashi.verdicts", {});

const signatureOf = (value: unknown) => JSON.stringify(value);

/** The verdict on `key` — only if it was given on exactly `value`; `null` otherwise. */
export function verdictOf(key: string, value: unknown): Verdict | null {
  const v = verdicts()[key];
  return v !== undefined && v.signature === signatureOf(value) ? v : null;
}

export function isConfirmed(key: string, value: unknown): boolean {
  return verdictOf(key, value)?.verdict === "confirmed";
}

export function recordVerdict(
  key: string, value: unknown, verdict: Verdict["verdict"], findings: Incompleteness[] = [],
) {
  // An updater, not `{...verdicts(), …}`: Solid 2 stages a signal write, so two calls in one
  // tick would each build off the same stale read and only the second would survive.
  setVerdicts((prev) => ({ ...prev, [key]: { signature: signatureOf(value), verdict, findings } }));
}

/** Kept for existing callers: a plain "confirmed" verdict. */
export function confirmDefinition(key: string, value: unknown) {
  recordVerdict(key, value, "confirmed");
}

export function forgetVerdict(key: string) {
  setVerdicts((prev) => {
    const next = { ...prev };
    delete next[key];
    return next;
  });
}

export const forgetConfirmation = forgetVerdict;

export function forgetAllVerdicts() {
  setVerdicts(() => ({}));
}
```

Import `type Incompleteness` from `./completeness` (type-only — no runtime cycle) and `issueFindings` from `./findings`. Then extend `reportRunIssues`:

```ts
/**
 * A run that failed to build says where, in the probe's shape. Written into `PROBE_STORE` (the
 * pointer next to Run pipeline reads it) and recorded as a *rejected* verdict on every item it
 * points at: a Run is the author asking, exactly like Confirm, so red is right here.
 */
export function reportRunIssues(issues: ProbeIssue[]) {
  const [, setProbe] = PROBE_STORE;
  setProbe((draft) => {
    draft.valid = false;
    draft.issues = issues;
  });
  const errors = issues.filter((issue) => issue.severity !== "warning");
  const byItem = new Map<string, ProbeIssue[]>();
  for (const issue of errors) {
    const parts = issue.pointer.split("/");
    const key = parts[1] === "nodes" ? `node:${parts[2]}` : parts[1] === "groups" ? `group:${parts[2]}` : null;
    if (key === null) continue;
    byItem.set(key, [...(byItem.get(key) ?? []), issue]);
  }
  for (const [key, own] of byItem) {
    const value = key.startsWith("node:")
      ? cards.nodes[Number(key.slice(5))]?.card
      : cards.groups[key.slice(6)];
    if (value === undefined) continue;
    recordVerdict(key, value, "rejected", issueFindings(own));
  }
}
```
